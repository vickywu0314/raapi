# 随访字段清单（以《RA 数据库字段》思维导图为准）

新增随访 / 编辑随访 / 访视详情的字段。**2026-10-06 起 2~7 组以 `docs/老系统字段/RA数据库字段-思维导图.pdf` 为准**（业务提供），
基本信息（第 1 组）按此前对照老系统 H5 截图定好的不再改。只参考字段、选项、顺序，不参考样式。

图例：✅ 字典已有（库字段已知）　🆕 PDF 有、字典没有（库字段待查，查不到则自定义）　📦 字典有、PDF 没有（老数据有值，保留显示）
PDF 里的错别字按正确写法列出，并在「说明」里注明；选项文字最终以库里老数据实际存的为准（待查数据核对）。
存库格式对齐 `patient_follow_up_history` 里老系统已存的数据（见 `docs/随访字段字典.md`）；「库字段」标 ❓ 的要查老系统实际怎么存后再定。

老系统录随访分 7 组：基本信息、病史病情、辅助检查、病情评估、中医诊断、治疗方案、不良反应。
没有单独的「不良事件」组：SAE、措施、不良事件详情都在「不良反应」组里，也存在 `blsj`（已确认）。`bblsj` 的用途仍不清楚，新增随访不写它。
基本信息在新增随访时只读，不录入。

老系统新增随访写表的规律（2026-10-06 查最近 3 条）：`follow_up_date` 写日期（00:00:00），`followUpDate` 为 NULL，
`last_follow_up_id` = 该患者上一次随访 id，`status` = 1。

## 1. 基本信息（只读，取 `patient_basic_info`）· 已收齐

老系统 H5 的基本信息：姓名、手机号、身份证号、性别、身高、体重、腰围、心率、收缩压、舒张压、婚史（已婚/未婚/离异/丧偶）、吸烟史（无/有）、民族（汉族/其他民族）。
我们原有的全部保留，补上老系统有而我们缺的 4 项（2026-10-06）：

| 字段 | 库字段 |
|---|---|
| 腰围（cm） | `waistline` |
| 心率（次/分） | `xl` |
| 收缩压 / 舒张压（mmHg） | `xy_h` / `xy_l`；`xy_h` 为空时用 `xy` |
| ACR/EULAR 2010 分类标准总分 | `acr_eular_score`（空则 `acrEularScore`）；≥6 分符合 RA 分类 |

ACR/EULAR 2010（老系统基本信息第 2~6 页）：受累关节数量（1 个中大关节 0 / 2-10 个中大关节 1 / 1-3 个小关节 2 / 4-10 个小关节 3 / >10 个小关节 5）、
血清学抗体检测（均阴性 0 / 至少一项低滴度阳性 2 / 至少一项高滴度阳性 3）、滑膜炎持续时间（<6 周 0 / ≥6 周 1）、
急性时相反应物（CRP 或 ESR 均正常 0 / 增高 1），相加得总分。老系统只存总分，`acr_eular_info` 全空。
新增随访只读显示总分；重新评估放到新建患者 / 编辑档案，各部分选项存新表。

待确认：
- [x] `xy` = 收缩压的另一份（查数据 xy 与 xy_h 完全相同）
- 数据问题：有 xy_h=80、xy_l=120 这类收缩压 < 舒张压的，疑似填反；原样显示，放进数据核查规则

PDF「食之纳差」老数据存「食少纳差」。舌色「绛」老数据就是正确写法。

方案：页面一律显示正确写法；新写入用老数据里最多的那种写法（统计口径不变），读老数据时把另一种写法也认作同一选项。
