## 1. 工具与隔离数据库

后端为Java8、Spring Boot2.2.0.RELEASE、Maven项目，没有根reactor；现有Lombok1.18.0不能直接换Java17编译。使用Java8及Maven3.9.x，先确认 `java -version`、`javac -version`、`mvn -version` 都指向预期工具。前端仪器要求Node≥20，已使用Node24.19/npm11.9；开发代理只用Node标准库，不需要前端构建。

```sh
export JAVA_HOME='/absolute/path/to/jdk8'
export PATH="$JAVA_HOME/bin:/absolute/path/to/maven/bin:$PATH"
java -version
javac -version
mvn -version
node --version
```

隔离调试使用MySQL8.4/InnoDB和loopback上的独立 `ra_synthetic_test` 库；已有技术验证的版本为8.4.11，不能据此证明其它目标版本兼容。自行安装数据库或使用本机已有的专用实例，不复制他人的私有activate脚本，也不接管正在被其它任务使用的库/端口。

在仓库外保存权限受限的MySQL客户端配置，例如 `/absolute/private/mysql-client.cnf`：

```ini
[client]
protocol=TCP
host=127.0.0.1
port=43306
user=<LOCAL_DB_USER>
password=<LOCAL_DB_PASSWORD>
```

以下操作仅用于新建空合成库；库已存在时先确认归属及是否为空，不重放seed。账号应具有本次合成建库/建表权限；应用账号另按实际读取范围配置。

```sh
mysql --defaults-extra-file=/absolute/private/mysql-client.cnf \
  --execute='CREATE DATABASE ra_synthetic_test CHARACTER SET utf8mb4;'
mysql --defaults-extra-file=/absolute/private/mysql-client.cnf \
  --database=ra_synthetic_test \
  < raapi/src/test/resources/ai-analysis-real-data/p00/schema.sql
mysql --defaults-extra-file=/absolute/private/mysql-client.cnf \
  --database=ra_synthetic_test \
  < raapi/src/test/resources/ai-analysis-real-data/p01/seed-overview.sql
```

这组文件覆盖合成AI首页概览、搜索和本人患者读取：schema包含 `patient_basic_info`、`patient_relation_doctor`、`patient_follow_up_history`、`patient_comorbidity`、`user`、`patient_audit_log`、`patient_ra_extra` 七表；seed含医生101的六位RA患者及医生202的他人患者。`patient_ra_extra` 在该schema中仅有三项读取列，可保持空表，对应信息为未填写。

若要专测大Long导航，在另一空合成库使用同一schema及 [p00/seed.sql](../src/test/resources/ai-analysis-real-data/p00/seed.sql) **替代** overview seed；它含超过JS安全整数及Long最大值的合成患者/访视。两份seed是替代场景，不叠加。测试fixture会创建并清理自己拥有的表，不能同时跑在手工导入的库上。

这不是完整普通CRUD安装：生产 [patient_ra_extra DDL](../src/main/resources/sql/20261011_patient_ra_extra.sql) 还有写入者和时间列，普通写入、OCR、质控处理等另有前置结构。完整空库安装顺序尚未整理；按 [TODO上线前资料](TODO.md) 与实际目标schema核对。不要通配执行历史SQL、生产研究编号回填，或把 [结构调研快照](../../docs/schema/README.md) 当迁移脚本。

## 2. 私有配置、两个进程与登录

在仓库外创建仅本机可读的 `/absolute/private/ra-local.properties`。下面密码都是占位符，必须替换；本地账号格式为 `用户名:密码:医生ID`，多个账号逗号分隔。

```properties
server.address=127.0.0.1
server.port=8065
spring.datasource.url=jdbc:mysql://127.0.0.1:43306/ra_synthetic_test?characterEncoding=utf8&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai
spring.datasource.username=<LOCAL_DB_USER>
spring.datasource.password=<LOCAL_DB_PASSWORD>
ra.auth.accounts=synthetic:<LOCAL_TEST_PASSWORD>:101

ra.ai.api.enabled=true
ra.ai.gateway.enabled=false
ra.ai.gateway.outbound-approved=false
ra.ai.gateway.endpoint=https://api.deepseek.com/chat/completions
ra.ai.gateway.model=deepseek-flash
ra.ai.gateway.proxy-mode=direct
ra.ai.gateway.synthetic-loopback=false
ra.ai.chat.enabled=false
ra.ai.chat.aggregate-outbound-approved=false
ra.ai.chat.clinical-outbound-approved=false
ra.ai.chat.endpoint=https://api.deepseek.com/chat/completions
ra.ai.chat.model=deepseek-flash
ra.ai.chat.proxy-mode=direct
ra.ai.chat.synthetic-loopback=false
ra.export.smtp.enabled=false
```

第一个终端启动后端，等待日志确认Tomcat已在8065就绪；该命令不运行测试：

```sh
mvn -B -f raapi/pom.xml -DskipTests spring-boot:run \
  -Dspring-boot.run.arguments="--spring.config.additional-location=file:/absolute/private/ra-local.properties"
```

第二个终端启动前端同源代理：

```sh
node raweb/scripts/dev-server.mjs --port 8090 \
  --upstream http://127.0.0.1:8065
```

也可从 `raweb/` 执行 `npm run dev` 使用相同默认端口；它不会自动打开浏览器。代理只接受显式loopback HTTP上游，只监听127.0.0.1，透传Cookie/Set-Cookie及Trace，不注入身份；这是开发服务，不是正式反向代理部署方案。保持 `RA_CONFIG.apiBase` 未覆盖即可使用同源路径。

打开 `http://127.0.0.1:8090/login.html`，用私有配置中的 `synthetic` 账号登录，再打开 `http://127.0.0.1:8090/ai-analysis.html`；提交患者搜索后沿链接查看档案。overview seed还可直接查看 `patient-visits.html?id=1&from=ai-analysis`。模型关闭仍可调试概览、搜索和患者读取。

实际 `/api/ra/auth/login` 校验配置账号、替换旧会话并安装 `AuthenticatedDoctorSession`；可信入口的 `PrincipalProvider` 只消费该typed身份。`/auth/me` 返回显示信息，匿名为HTTP200业务code401；可信患者接口匿名为HTTP401。浏览器存储、请求doctorId、header或URL的from均不能安装身份。本地配置账号用于合成调试，不替代正式authenticator接收。

## 3. DeepSeek key与两套独立配置

key仅由后端私有配置或服务器进程的秘密注入提供，不放前端、URL、Git或日志。解析与问答都接受环境变量 `RA_AI_API_KEY` 作为fallback；也可在同一私有properties中按功能分别设置：

```properties
ra.ai.gateway.api-key=<SERVER_ONLY_DEEPSEEK_KEY>
ra.ai.chat.api-key=<SERVER_ONLY_DEEPSEEK_KEY>
```

功能属性存在时优先使用它，**空属性也会遮蔽 `RA_AI_API_KEY`**；采用环境注入时删除相应api-key属性，而非留空。合法key为1–512个可打印ASCII字符，不包含空格。不要输出环境值或把key作为Maven命令行参数。设置key本身不会启用模型。

| 项目 | 解析gateway | 问答chat |
|---|---|---|
| 开关 | `ra.ai.gateway.enabled`，默认false | `ra.ai.chat.enabled`，默认false |
| 出站范围 | `ra.ai.gateway.outbound-approved`，默认false | ALL/COHORT使用 `ra.ai.chat.aggregate-outbound-approved`；PATIENT使用 `ra.ai.chat.clinical-outbound-approved`，均默认false |
| endpoint | `ra.ai.gateway.endpoint` | `ra.ai.chat.endpoint` |
| 生产地址 | 仅 `https://api.deepseek.com/chat/completions` | 同左 |
| model | `ra.ai.gateway.model` 默认空；必须为非空 `[A-Za-z0-9._-]{1,64}`，当前接收使用deepseek-flash | `ra.ai.chat.model` 默认且生产限定deepseek-flash |
| key | `ra.ai.gateway.api-key` → 缺失才用 `RA_AI_API_KEY` | `ra.ai.chat.api-key` → 缺失才用 `RA_AI_API_KEY` |
| proxy | `ra.ai.gateway.proxy-mode` | `ra.ai.chat.proxy-mode` |

合成解析调试需同时将 `ra.ai.gateway.enabled=true` 和 `ra.ai.gateway.outbound-approved=true`；合成ALL/COHORT问答需 `ra.ai.chat.enabled=true` 和 `ra.ai.chat.aggregate-outbound-approved=true`。PATIENT问答另取clinical许可，不继承aggregate。没有选中的功能/范围保持关闭。

开关/许可只接受精确 `true` / `false`。修改启动配置后重启进程；chat凭据在对应范围首次获准后读取并缓存。合成技术调试不需要真实患者数据：模型关闭时不需key；要接收真实模型的合成输入时只启用所选功能及所选合成范围。临床病例出站、正式医学/字典/文件与目标部署许可仍按 [正式接收边界](AI队列发布与回滚手册.md) 分别核实，不能由key或许可配置值代替接收。

`synthetic-loopback=true` 是测试peer特例，严格绑定各自测试model/key与127.0.0.1端口；它不表示“用合成输入请求真实DeepSeek”，真实DeepSeek仍保持false。显式真实合成测试的 `DEEPSEEK_MODEL`、`RA_TEST_DEEPSEEK_SYNTHETIC` 仅是ReceptionIT前置，不替代上表应用属性；准确命令与计数见 [测试指南P04a](测试运行指南.md#ai-分析真实数据-p04a官方缓存字段与受控代理真实合成接收)。

### 服务器代理

`direct` 为缺省，明确禁用代理；`system` 使用JVM的 `ProxySelector`。仅设置shell的 `HTTPS_PROXY` 不证明JVM已使用它。若实际环境需要HTTPS代理，在相应proxy-mode改为system后，用已核实的代理host/port传给后端JVM，例如：

```sh
mvn -B -f raapi/pom.xml -DskipTests spring-boot:run \
  -Dspring-boot.run.arguments="--spring.config.additional-location=file:/absolute/private/ra-local.properties" \
  -Dspring-boot.run.jvmArguments="-Dhttps.proxyHost=<PROXY_HOST> -Dhttps.proxyPort=<PROXY_PORT>"
```

两个网关仍只向固定DeepSeek地址发送一次请求，不跟随重定向或自动重试；网络预算4500ms、总预算5000ms。前端同源代理和服务器出站代理是不同配置。

## 4. 扩展功能DDL与失败定位

上述最短种子不包含AI持久结果、私有条件、比较、解析/问答审计和导出申请表。需要相应功能时先核对目标结构，再按 [发布手册SQL清单](AI队列发布与回滚手册.md#4-sql清单与留存) 逐文件准备：analysis run → private definition/command → compare run → parse audit → export audit → export request → chat audit；旧 `export_application` 是申请前置。手册列出七份新DDL/八张表和权限；部分成功不盲重放。队列/分页还需服务器注入 `ra.ai.analysis.cursor-key-base64`（标准Base64解码至少32字节）；缺失不阻止其它bean启动，但相关分析会拒绝。普通写入/OCR等结构仍沿上文范围核对，不因这些DDL齐备而宣称全站安装完整。

| 观察 | 实际条件与排查 |
|---|---|
| 代理502 / 504 | 8065不可连接 / 上游60秒未响应；先查后端日志，不归因模型key |
| `UNAUTHENTICATED` | 缺typed会话；检查同源登录与Cookie，不用本地存储或doctorId绕过 |
| `FORBIDDEN` / `RESOURCE_NOT_FOUND` | 医生提示不一致或患者不可访问；不放宽范围 |
| `SERVICE_UNAVAILABLE` | 先查API启动门、所需表/字段、连接及分析cursor配置；不打印凭据 |
| `AI_NOT_ENABLED` | enabled恰为false，包括缺省false；不是key缺失的错误 |
| `AI_NOT_APPROVED` | enabled=true且approved=false |
| `AI_CONFIG_UNAVAILABLE` | parse按顺序检查enabled非法值、approved非法值及endpoint/model/key/proxy/synthetic配置；chat也拒绝非规范值/无效凭据配置 |
| `CHAT_DISABLED` / `CHAT_OUTBOUND_NOT_APPROVED` | chat独立关闭 / 所选范围的独立许可拒绝 |
| `AI_HTTP_ERROR` / `AI_IO_ERROR` / `AI_TIMEOUT` | peer非200 / 网络I/O / 有界预算；HTTP错误不能一概认定key错误 |
| `AI_INVALID_RESPONSE` | 模型协议响应不合约；不能弱化响应校验来调通 |

parse可能返回HTTP200/RULE并携fallback，不能只凭200宣称真实模型成功；成功接收需核engine/model/fallback及原候选协议。日志排查使用有限错误码和Trace，不采集key、问题/患者原文或Authorization。

本指南不执行SQL、真实模型或部署。普通CRUD完整空库安装、正式目标工件/host/启动与流量切换/回退渠道仍需目标维护者补齐；现有 [发布与回滚手册](AI队列发布与回滚手册.md) 拥有正式接收要求，[测试指南](测试运行指南.md) 与 [前端仪器](../../raweb/tests/README.md) 拥有验证命令。构建成功、合成验证或browser发现列表都不是正式部署或浏览器场景通过证据。
